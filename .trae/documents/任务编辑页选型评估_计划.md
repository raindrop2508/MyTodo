# 任务编辑页 UI 规划

## Summary

* 结论：基于现有实现，**单独新开** `TaskEditActivity` 最合适，不在 `TaskDetailActivity.kt` 内直接切换成编辑态。

* 范围：本次**只完成 UI 页面与页面跳转**，使用 Mock 数据展示，不接入保存、回传、Repository、ViewModel 等真实逻辑。

* 参考基线：

  * 表单风格参考 `app/src/main/res/layout/bottom_sheet_add_task_placeholder.xml`

  * 详情展示风格参考 `app/src/main/java/com/gordon/mypotato/ui/tasks/TaskDetailActivity.kt`

* 目标结果：从 `TaskDetailActivity` 顶部 `MaterialToolbar` 的编辑按钮进入新的任务编辑页，页面整体视觉与现有详情页、添加任务 BottomSheet 保持一致。

## Current State Analysis

### 1. `TaskDetailActivity` 已具备详情页视觉基线

* 文件：`app/src/main/java/com/gordon/mypotato/ui/tasks/TaskDetailActivity.kt`

* 现状：

  * 已具备顶部 `MaterialToolbar`、基础信息区、标签区、内容区、长时任务步骤区、番茄钟入口。

  * 右上角 `action_edit` 菜单当前只打印日志，没有跳转行为。

* 结论：

  * 这个页面适合作为“编辑页入口”，不适合继续在同一个 Activity 中承载完整表单。

### 2. 添加任务 BottomSheet 已具备编辑页表单基线

* 文件：`app/src/main/res/layout/bottom_sheet_add_task_placeholder.xml`

* 文件：`app/src/main/java/com/gordon/mypotato/ui/common/AddTaskBottomSheetHelper.kt`

* 现状：

  * 已包含标题、内容、备注、任务类型切换、分类、紧急/重要开关、步骤编辑区。

  * 风格上已经和当前项目的 Material 视觉体系保持一致。

* 结论：

  * 新编辑页可以直接沿用这套 UI 结构，而不是从空白页面重新设计。

### 3. 步骤编辑能力已有公共组件可复用

* 文件：`app/src/main/java/com/gordon/mypotato/ui/common/EditableStep.kt`

* 文件：`app/src/main/java/com/gordon/mypotato/ui/common/EditableStepAdapter.kt`

* 文件：`app/src/main/res/layout/item_step_editable.xml`

* 现状：

  * 子任务编辑列表、删除按钮、拖拽手柄样式都已经存在。

* 结论：

  * 编辑页中的“长时任务步骤区”可以直接复用现有公共组件，只喂入 Mock 数据即可。

### 4. 当前范围不需要处理真实业务闭环

* 用户明确要求：

  * 只完成 UI。

  * 内容使用 Mock 数据。

  * 不涉及保存逻辑、回传逻辑、持久化逻辑。

* 结论：

  * 本次不需要设计 `setResult()`、共享状态、Fake Repository、刷新列表等实现。

  * 所有按钮仅保留界面占位和基础交互反馈即可。

## Assumptions & Decisions

* 决策 1：新增 `TaskEditActivity`，不修改 `TaskDetailActivity` 的主体布局职责。

* 决策 2：`TaskDetailActivity` 只负责通过 Toolbar 编辑按钮跳转到 `TaskEditActivity`。

* 决策 3：`TaskEditActivity` 使用整页 Activity 布局，不复用 BottomSheet 作为容器。

* 决策 4：编辑页 UI 采用“详情页卡片感 + BottomSheet 表单结构”的组合方案。

* 决策 5：页面数据全部使用 Mock：

  * 标题、内容、备注、分类、紧急/重要状态、任务类型、步骤列表均使用写死数据或 Intent 初始化后的 Mock 展示。

* 决策 6：本次不改 `TodayFragment.kt`、`TasksFragment.kt` 的 FAB 新建入口。

* 决策 7：本次不实现：

  * 保存

  * 删除

  * 编辑结果回传

  * 数据刷新

  * 数据层统一

* 决策 8：凡是本次先保留占位、后续还要继续实现的入口、按钮或方法，统一补充中文 `TODO:` 标记。

## Proposed Changes

### 1. 新增 `app/src/main/java/com/gordon/mypotato/ui/tasks/TaskEditActivity.kt`

* 页面职责：

  * 承载任务编辑页 UI。

  * 读取来自 `TaskDetailActivity` 的基础参数，用于区分当前展示的是“单次任务”还是“长时任务”。

  * 其余表单内容使用 Mock 数据填充，保证页面展示完整。

* 页面内容建议：

  * 顶部 `MaterialToolbar`

  * 标题输入框

  * 内容输入框

  * 备注输入框

  * 任务类型切换区

  * 分类选择区

  * 紧急/重要开关区

  * 长时任务步骤编辑区

  * 底部主按钮或 Toolbar 保存按钮占位

* 交互范围：

  * 返回按钮可直接 `finish()`

  * 保存按钮仅做占位展示或日志输出，不做实际保存

  * 类型切换仅处理步骤区域显隐

### 2. 新增 `app/src/main/res/layout/activity_task_edit.xml`

* 布局目标：

  * 形成完整编辑页，而不是弹层样式。

* 布局来源：

  * 参考 `bottom_sheet_add_task_placeholder.xml` 的表单区块

  * 参考 `activity_task_detail.xml` 的留白、卡片、间距、标题层级

* 推荐结构：

  * 根节点使用纵向布局，顶部为 `MaterialToolbar`

  * 内容区使用 `NestedScrollView`

  * 主表单区用 `MaterialCardView` 承载，提升与详情页的一致性

  * 长时任务步骤区继续用单独卡片承载

* 视觉要求：

  * 沿用现有颜色、圆角、描边、间距体系

  * 不引入新的 UI 风格分支

### 3. 新增 `app/src/main/res/menu/menu_task_edit.xml`

* 用途：

  * 为编辑页 Toolbar 提供“保存”操作入口。

* 说明：

  * 仅做 UI 占位，不绑定真实保存逻辑。

* 原因：

  * 与 `TaskDetailActivity` 顶部 Toolbar 操作风格保持一致。

### 4. 更新 `app/src/main/AndroidManifest.xml`

* 目标：

  * 注册 `TaskEditActivity`。

* 原因：

  * 当前清单中还没有任务编辑页 Activity。

### 5. 更新 `app/src/main/java/com/gordon/mypotato/ui/tasks/TaskDetailActivity.kt`

* 修改点：

  * 将 Toolbar 中的 `action_edit` 从日志行为改为启动 `TaskEditActivity`。

  * 透传最少必要参数，例如：

    * `taskId`

    * `taskTitle`

    * `isLongTask`

    * `category`

    * `urgent`

    * `important`

* 范围控制：

  * 不处理结果回调

  * 不刷新详情页

  * 不修改删除逻辑

* `TODO` 标记要求：

  * `action_delete` 对应处理保留占位，但增加 `TODO: 后续接入删除确认与删除逻辑`

  * 编辑跳转完成后，增加 `TODO: 后续接入编辑结果回传并刷新详情页`

* 原因：

  * 满足“从任务详情页顶部 Toolbar 页面跳转”的明确需求。

### 6. 复用现有公共编辑组件

* 直接复用：

  * `EditableStep.kt`

  * `EditableStepAdapter.kt`

  * `item_step_editable.xml`

* 用法：

  * `TaskEditActivity` 内部准备一组 Mock 步骤数据。

  * 当任务类型为长时任务时展示步骤编辑卡片。

  * 当任务类型为单次任务时隐藏步骤编辑卡片。

* 原因：

  * 既满足 UI 完整度，又避免重复实现步骤编辑列表外观。

### 7. 需要补充的资源

* 可能需要新增或补充：

  * `strings.xml` 中的任务编辑页标题、保存文案、备注文案等字符串

* 原则：

  * 尽量复用已有字符串

  * 仅在现有资源无法覆盖时新增

### 8. 为未实现能力增加显式 TODO

* `app/src/main/java/com/gordon/mypotato/ui/tasks/TaskEditActivity.kt`

  * 保存按钮点击位置增加 `TODO: 后续接入任务保存逻辑`

  * Mock 数据初始化位置增加 `TODO: 后续改为真实任务数据源`

  * 长时任务步骤区若仅做展示，增加 `TODO: 后续接入步骤增删改与排序逻辑`

* `app/src/main/java/com/gordon/mypotato/ui/tasks/TaskDetailActivity.kt`

  * 编辑跳转逻辑旁增加 `TODO: 后续接入编辑结果回传`

  * 删除按钮点击逻辑增加 `TODO: 后续接入删除确认弹窗与删除逻辑`

* `app/src/main/res/menu/menu_task_edit.xml`

  * 若保留保存入口但暂不实现，对应点击处理增加 `TODO: 后续接入保存校验与提交流程`

* 标记规范：

  * 统一使用 `TODO:` 前缀

  * 注释内容使用中文，直接写明后续动作

  * 仅对真实未完成且后续有明确方向的能力添加，不做泛化堆积

## Implementation Notes

* 页面结构建议采用“一个主信息卡片 + 一个步骤卡片”的双卡片结构，与 `TaskDetailActivity` 视觉保持连续。

* 标题、内容、备注输入框继续沿用 `Material3 TextInputLayout` 风格，与 `AddTaskBottomSheetHelper` 当前表单样式保持统一。

* 分类、紧急、重要、任务类型这些区块，优先沿用已有控件样式和资源，避免新建一套视觉规范。

* 若 `TaskDetailActivity` 传入的是长时任务，则编辑页默认展示步骤区；若为单次任务，则默认隐藏。

* 若未传入足够参数，编辑页允许直接使用本地 Mock 默认值兜底，保证页面可展示。

## Verification Steps

* 跳转验证：

  * 从 `TaskDetailActivity` 点击右上角编辑按钮，可进入 `TaskEditActivity`

  * 返回按钮可正常退出编辑页

* UI 验证：

  * 编辑页包含标题、内容、备注、类型、分类、紧急/重要、步骤区等完整表单模块

  * 页面整体留白、卡片、字号、按钮风格与任务详情页、添加任务 BottomSheet 一致

* Mock 验证：

  * 页面默认能展示完整 Mock 内容

  * 单次任务与长时任务能展示不同 UI 形态

* 范围验证：

  * 不新增真实保存逻辑

  * 不新增数据回传逻辑

  * 不修改 `TodayFragment.kt` 与 `TasksFragment.kt` 的新增任务流程

  * 所有已暴露但暂未实现的入口，都有明确 `TODO:` 标记

## Final Recommendation

* 推荐方案：**新建** **`TaskEditActivity`，只做 UI 骨架与跳转**

* 不推荐方案：**在** **`TaskDetailActivity.kt`** **中直接混入完整编辑表单**

* 执行顺序：

  1. 新建编辑页 Activity、布局、Toolbar 菜单
  2. 在详情页编辑按钮接入页面跳转
  3. 用 Mock 数据补齐长时/单次两种编辑态展示
