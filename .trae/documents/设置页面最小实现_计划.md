# 设置页面最小实现计划

## Summary
- 目标：基于 `docs` 设计规范、Web 原型 `src/pages/Settings.tsx` 与用户给定截图，把 `SettingsFragment` 从占位页改为“最小可演示设置页”。
- 本次范围：标题、主题模式（跟随系统/浅色/深色）、番茄钟参数（专注/休息分钟）、数据导入/导出按钮、版本号展示。
- 交互深度：采用“可交互占位”方案；主题与番茄钟参数仅在当前页面内更新 UI，导入/导出只提供 Toast 或对话框占位反馈，不做真实文件读写与持久化。

## Current State Analysis
- `app/src/main/java/com/gordon/mypotato/ui/settings/SettingsFragment.kt` 目前仅继承 `Fragment(R.layout.fragment_settings)`，没有 ViewBinding、状态或交互逻辑。
- `app/src/main/res/layout/fragment_settings.xml` 目前只有一个居中的 `TextView`，与 `fragment_today.xml`、Web 原型和截图都不一致。
- `docs/ui-skeleton-android/page_design.md`、`docs/ui_skeleton/UI骨架验收清单.md` 都要求 Settings 页采用纯 XML + Material3，至少具备主题模式、数据管理和版本信息入口；用户另外要求加入番茄钟参数。
- `mypotato-focus-flow-main/src/pages/Settings.tsx` 已给出可参考的信息架构：顶部标题、副标题、主题分组、番茄钟参数、导入导出区、底部版本号。
- 当前 Android 工程中没有现成的设置持久化、文件导入导出、`AppCompatDelegate` 主题模式切换封装或 Activity Result 文件选择实现。
- `app/build.gradle` 已声明 `versionName = "1.0"`，因此版本展示可直接通过 `BuildConfig.VERSION_NAME` 读取，无需修改 Gradle。

## Proposed Changes

### 1. 重构 `app/src/main/res/layout/fragment_settings.xml`
- 将根布局改为 `NestedScrollView` + 内容容器，符合文档对小屏滚动的要求。
- 顶部区域改为左上对齐标题和应用名副标题，视觉结构对齐截图与 Web 原型。
- 新增三个设置分组卡片，使用 `MaterialCardView`/`LinearLayout` 组织：
  - 主题模式：3 个并列可选按钮，分别对应“跟随系统 / 浅色 / 深色”。
  - 番茄钟参数：2 个数字输入框，分别展示“专注分钟 / 休息分钟”。
  - 数据管理：导出 JSON、导出 CSV、导入 JSON 三个入口按钮。
- 页面底部增加版本号文案区域，展示 `MyPotato · v1.0` 样式信息。
- 样式原则：
  - 尽量复用主题属性 `?attr/colorSurface`、`?attr/colorOnSurface`、`?attr/colorOutlineVariant`。
  - 圆角、间距、卡片层级与现有 `Today` 页面保持同一风格。
  - 优先使用系统 drawable / Material 图标占位，避免为最小实现引入额外依赖。

### 2. 扩展 `app/src/main/res/values/strings.xml`
- 补齐设置页所需全部文案资源，避免在 Kotlin/XML 中出现用户可见硬编码文本：
  - 标题、副标题、分组标题。
  - 主题模式三项文案。
  - 番茄钟参数标签与输入提示。
  - 导入导出按钮文案与占位提示文案。
  - 版本号格式化文案。
- 保持本次实现以中文文案为主，与当前项目大部分页面一致。

### 3. 实现 `app/src/main/java/com/gordon/mypotato/ui/settings/SettingsFragment.kt`
- 改为使用 `FragmentSettingsBinding` 管理视图，遵循项目中 `TodayFragment` / `TasksFragment` 的实现方式。
- 在 Fragment 内维护最小页面状态：
  - `selectedThemeMode`：`SYSTEM` / `LIGHT` / `DARK`
  - `focusMinutes`：默认 25
  - `breakMinutes`：默认 5
- 主题模块交互：
  - 为三个主题按钮绑定点击事件。
  - 点击后刷新选中态外观（选中按钮高亮、未选中恢复默认边框/文字色）。
  - 同时给出 Toast 占位反馈，明确“当前仅切换演示态，未持久化”。
- 番茄钟参数交互：
  - 初始化输入框默认值 25 / 5。
  - 监听输入变化，做最小校验：空值或非法数字回退到 1；限制区间可控制在 1~120。
  - 参数仅保存在当前 Fragment 生命周期内，不写入仓库或本地存储。
- 数据管理交互：
  - “导出 JSON”“导出 CSV”“导入 JSON”按钮点击后，使用 Toast 或 `MaterialAlertDialogBuilder` 给出占位提示。
  - 不接入 `ACTION_CREATE_DOCUMENT` / `ACTION_OPEN_DOCUMENT`，避免超出本次最小实现范围。
- 版本号展示：
  - 通过 `BuildConfig.VERSION_NAME` 组装底部版本文案。
- 公共辅助：
  - 参考 `TodayFragment`/`TasksFragment` 中的主题色解析方式，封装 `resolveThemeColor()` 或等效方法，用于按钮选中态更新。

### 4. 验证与质量收口
- 编辑完成后检查 `SettingsFragment.kt` 和相关资源的编译诊断，确认没有 ViewBinding、资源引用或类型错误。
- 如布局命名发生绑定类变化，确保与 `FragmentSettingsBinding` 自动生成规则一致。

## Assumptions & Decisions
- 不引入语言模块、重置功能、检查更新入口；这些内容虽存在于文档/Web 原型，但不在本次用户确认范围内。
- 主题模式采用“页面内可交互占位”，不做应用级真实切换，也不做持久化；否则会扩展到 `MainActivity`、应用级状态和恢复逻辑。
- 数据导入/导出采用占位反馈，不接入文件系统与真实数据模型；否则需要补充 Activity Result、序列化模型、权限与错误处理。
- 番茄钟参数只做 UI 输入与基础校验，不与后续 Pomodoro 流程联动。
- 版本号以 `BuildConfig.VERSION_NAME` 为准，不新增独立配置源。

## Verification Steps
1. 读取 `fragment_settings.xml` 预览结构，确认页面包含标题、副标题、主题卡片、番茄钟参数卡片、数据管理卡片、版本号。
2. 检查 `SettingsFragment.kt` 诊断，确认 ViewBinding、监听器和资源引用无错误。
3. 手动验证交互预期：
   - 点击主题按钮时选中态在三者之间切换，且出现占位反馈。
   - 番茄钟两个输入框默认展示 25 / 5，可编辑且非法值被兜底。
   - 导出 JSON / 导出 CSV / 导入 JSON 按钮均有占位反馈。
   - 页面底部正确显示版本号 `1.0`。
