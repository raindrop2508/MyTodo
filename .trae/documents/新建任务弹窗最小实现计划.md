# 新建任务弹窗（最小实现）计划

## 摘要
- 目标：参考 `docs/ui-skeleton-android` 文档、`mypotato-focus-flow-main` 的 `TaskEditor` 交互与你提供截图，实现 Android 端「新建任务弹窗」最小可用版本。
- 范围：本次仅落地弹窗 UI 与基础交互状态（输入、选中态、按钮响应），不接入 Room 持久化，不改造任务列表数据源。
- 成功标准：点击 Today 页 FAB 后出现与截图结构一致的弹窗，包含标题/描述/类型/分类/紧急重要/备注/取消保存，标题为空时不可保存（或保存无效反馈），可正常关闭。

## 现状分析（基于仓库事实）
- `TodayFragment` 已通过 `showAddTaskBottomSheet()` 打开 `BottomSheetDialog`，但当前仅加载占位布局与一个“确认（占位）”按钮。
- 弹窗布局文件为 `app/src/main/res/layout/bottom_sheet_add_task_placeholder.xml`，仅 3 个控件（标题、描述、按钮），与截图差距较大。
- 文档 `page_design.md` 已明确新增任务弹窗定位与控件结构；`lovable_ui_logic_file_map.md` 与 Web `TaskEditor.tsx` 已给出最小字段集合：`title/content/type/category/urgent/important/note`。
- 当前工程已启用 Material3（`Theme.Material3.DayNight.NoActionBar`），具备 `BottomSheetDialog` + Material 输入控件实现条件。

## 技术点（便于代码审查）
- Android XML（布局实现）
- Material3（Material Components）
- BottomSheetDialog（底部弹窗容器）
- Fragment + View 事件绑定（TodayFragment）
- 状态管理（最小本地 UI 状态，不落库）
- 表单最小校验（标题必填）

## 方案设计（决策完成）

### 1) 弹窗布局重构
- 文件：`app/src/main/res/layout/bottom_sheet_add_task_placeholder.xml`
- 改动：
- 使用垂直容器重构为截图对应结构：顶部拖拽条/标题与关闭按钮/标题输入/描述输入/TYPE 分段按钮/CATEGORY 单选标签/Urgent+Important 双按钮/Note 输入/底部 Cancel+Save。
- 输入框采用 `TextInputLayout + TextInputEditText`（或最小化 EditText + 自定义背景）保持圆角边框风格，优先使用主题属性色。
- 分类标签先按最小实现内置 5 项：`None/Work/Life/Study/Health`；其中 Work/Life/Study/Health 含彩色圆点。
- 保留 `BottomSheet` 容器形态，不新增全屏 Activity/DialogFragment。
- 原因：复用现有触发链路，最小改动满足截图与文档结构。

### 2) TodayFragment 弹窗交互逻辑升级
- 文件：`app/src/main/java/com/gordon/mypotato/ui/today/TodayFragment.kt`
- 改动：
- 在 `showAddTaskBottomSheet()` 中绑定新增控件的点击与状态切换逻辑。
- 增加最小本地状态字段（函数内局部变量即可）：`type`、`category`、`urgent`、`important`。
- 实现按钮选中态刷新方法（类型、分类、紧急、重要），采用卫语句（guard clause）减少嵌套。
- 实现标题必填校验：标题为空时阻止保存并给出最小反馈（例如输入框错误或日志提示）；非空时仅打印参数日志并关闭弹窗（占位保存）。
- 对关键方法补中文注释，注释说明功能、入参、出参、异常；并打印入参/出参日志，满足仓库规则。
- 原因：在不接入数据层的前提下完成可交互“最小闭环”。

### 3) 字符串资源补全
- 文件：`app/src/main/res/values/strings.xml`
- 改动：
- 新增弹窗相关文案资源：字段标题、占位提示、类型与分类枚举、按钮文案、校验文案。
- 替换现有占位文案（如 `today_bottom_sheet_title` 等）为真实“新建任务”语义。
- 原因：避免硬编码，便于后续国际化与维护。

### 4) 视觉资源最小补齐（按需）
- 文件（按最终实现择需）：
- `app/src/main/res/drawable/` 下新增 1~3 个 shape 资源（如输入框边框、分段按钮选中态、标签外框）
- `app/src/main/res/values/colors.xml`（若需要补充分类圆点色值）
- 改动：
- 仅补充截图必要视觉差异，优先复用主题色与现有 drawable（如 `bg_today_tag.xml`）。
- 严格控制资源数量，避免过度设计。
- 原因：保持“最小实现”目标，同时确保 UI 层次接近截图。

## 约束与边界
- 本次不改动 Room 实体、DAO、Repository，不新增数据库字段。
- 本次不实现真实“保存任务”业务，仅保留 TODO 接入点。
- 保持现有导航结构与 Today 页面主体布局不变，仅增强弹窗。
- 注释与日志遵循当前用户规则：中文注释、方法说明完整、关键入参出参打印。

## 假设与关键决策
- “最小实现”定义为：视觉结构 + 交互选中态 + 标题必填校验 + 占位保存回调（日志 + dismiss）。
- 弹窗形态采用 `BottomSheetDialog`（与现有代码和文档一致），不切换为居中 AlertDialog 风格。
- 分类数据使用前端原型同款静态枚举，不接入持久化配置。
- 不新增自动化测试；本次通过手动验证保障交付（UI 任务，变更集中且可视化强）。

## 实施顺序
1. 重构 `bottom_sheet_add_task_placeholder.xml` 完成控件骨架与 id 命名。
2. 在 `TodayFragment.showAddTaskBottomSheet()` 绑定控件并实现状态与校验。
3. 更新 `strings.xml` 与按需资源文件（`drawable/colors`）。
4. 本地编译与页面手动验收，修复明显样式或交互缺口。

## 验证步骤（执行阶段）
- 编译验证：`./gradlew :app:assembleDebug`
- 交互验证：
- 进入 Today 页点击 FAB，弹出“新建任务”弹窗。
- 可输入 Title/Description/Note，TYPE 在 One-time 与 Long task 间切换。
- CATEGORY 可在 None/Work/Life/Study/Health 之间切换并有选中态。
- Urgent/Important 按钮可独立切换选中态。
- 点击关闭按钮与 Cancel 能关闭弹窗。
- 标题为空点击 Save 不应成功提交；标题非空点击 Save 会记录日志并关闭弹窗。
- 代码质量验证：
- 检查新增方法注释是否为中文并含入参/出参/异常说明。
- 检查关键交互方法是否打印入参/出参日志。
- 使用诊断工具检查 `TodayFragment.kt` 与新增资源引用是否有错误。
