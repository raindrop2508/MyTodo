# 任务详情页步骤添加与进度联动计划

## Summary

- 目标 1：补全 `app/src/main/java/com/gordon/mypotato/ui/tasks/TaskDetailActivity.kt` 中“添加步骤”交互，使 `activity_task_detail.xml` 里的添加步骤入口真正可点击，并参考 `AddTaskBottomSheetHelper.kt` 的做法把新步骤插入到当前步骤列表。
- 目标 2：补全 `activity_task_detail.xml` 中“完成进度”数字和进度条，让它们根据子任务完成情况实时展示，不再写死为 `2/5` 和 `40`。
- 目标 3：让进度条已完成部分跟随 APP 主题色变化，避免继续使用固定黑色。
- 范围约束：本次只补 UI 交互与本地内存态联动，不接入持久化、Repository、页面回传或跨页面同步。

## Current State Analysis

### 1. `TaskDetailActivity.kt` 当前步骤列表是一次性写死渲染

- 文件：`app/src/main/java/com/gordon/mypotato/ui/tasks/TaskDetailActivity.kt`
- 现状：
  - `renderSteps()` 内部直接创建 `steps = listOf(...)`。
  - 渲染时只负责把写死步骤 inflate 到 `layoutStepList`。
  - `CheckBox` 仅设置 `isChecked`，没有监听勾选变化。
  - 页面级没有保存步骤状态的成员变量，因此无法支持“添加步骤后重新渲染仍保留状态”。
- 影响：
  - 添加步骤和进度联动都无法建立在稳定数据源上。

### 2. `activity_task_detail.xml` 的添加步骤入口只是静态文本

- 文件：`app/src/main/res/layout/activity_task_detail.xml`
- 现状：
  - `L294-L301` 的 “+ 添加步骤” `TextView` 没有 `id`。
  - 没有 `clickable`、`focusable`、`selectableItemBackgroundBorderless` 等交互反馈属性。
- 影响：
  - `ActivityTaskDetailBinding` 无法直接拿到该控件。
  - `TaskDetailActivity` 也无法绑定点击事件。

### 3. 完成进度区域完全是写死显示

- 文件：`app/src/main/res/layout/activity_task_detail.xml`
- 现状：
  - `tv_progress` 的文案固定为 `2/5`。
  - `ProgressBar` 的 `android:progress` 固定为 `40`。
- 影响：
  - 子任务勾选状态变化后，进度数字与进度条都不会变化。

### 4. 进度条 drawable 目前使用固定黑色，不跟主题走

- 文件：`app/src/main/res/drawable/bg_progress_bar_black.xml`
- 现状：
  - 进度条前景颜色写死为 `#1A1A1A`。
  - 该 drawable 只被 `activity_task_detail.xml` 单点使用。
- 影响：
  - 当主题主色调整时，进度条颜色不会同步变化。
- 结论：
  - 可以直接更新该 drawable 为 `?attr/colorPrimary`，或改名/新建专用 drawable。
  - 因为当前只有任务详情页使用，直接改现有 drawable 成本最低。

### 5. 已有“添加步骤”的参考实现存在于其它页面

- 文件：`app/src/main/java/com/gordon/mypotato/ui/common/AddTaskBottomSheetHelper.kt`
- 现状：
  - `tvAddStep.setOnClickListener` 会向 `stepList` 追加一个新的 `EditableStep("")`。
  - 该思路已经验证过“点击添加 -> 数据列表追加 -> UI 刷新”的基本模式。
- 结论：
  - 任务详情页可复用同样的数据驱动思路，只是这里用的是 `StepMock` + `layoutStepList` 手动渲染，而不是 RecyclerView。

## Assumptions & Decisions

- 决策 1：在 `TaskDetailActivity` 中新增页面级 `MutableList<StepMock>` 作为步骤数据源，替代 `renderSteps()` 内部局部写死列表。
- 决策 2：`StepMock` 改为可变字段数据结构，以支持：
  - 新增步骤
  - 勾选完成状态切换
  - 完成时间文案联动
- 决策 3：点击“添加步骤”时，新增一个默认未完成步骤并立即重新渲染步骤列表。
- 决策 4：进度展示规则统一为：
  - 数字：`已完成数/总数`
  - 进度条：`(已完成数 / 总数) * 100`
  - 当总数为 0 时，显示 `0/0`，进度值为 `0`
- 决策 5：添加步骤功能仅在长时任务模式下生效，与当前页面结构保持一致。
- 决策 6：进度条完成色使用主题属性 `?attr/colorPrimary`，保证主题变化时自动联动。
- 决策 7：对本次未实现的后续能力增加 `TODO:` 标记，例如：
  - 后续接入步骤标题编辑
  - 后续接入步骤删除能力
  - 后续接入真实任务数据源

## Implementation Notes

- `renderLongTask()` 中不要每次都重新覆盖整个步骤初始列表，否则用户新加的步骤会丢失。
- 推荐在 `onCreate()` 或首次进入长时任务时只初始化一次步骤数据。
- `CheckBox` 监听里需要避免只更新视图不更新数据，否则再次重渲染会丢失状态。
- 添加步骤时建议默认：
  - `title = "新步骤"`
  - `time = ""`
  - `done = false`
  - `doneTime = ""`
- 完成时间文案可继续沿用当前页面已有格式，例如 `完成于 yyyy/M/d HH:mm:ss`，也可先用简单 Mock 文案。
- 需要在方法内增加中文 `TODO:` 标记，至少覆盖：
  - 步骤标题编辑能力
  - 步骤删除能力
  - 后续接入真实数据源

## Verification Steps

- 交互验证：
  - 长时任务详情页点击“+ 添加步骤”后，列表新增一条未完成步骤。
  - 单次任务详情页不会展示步骤卡片，不受本次改动影响。
- 状态验证：
  - 勾选/取消勾选任一步骤后，步骤透明度、完成时间文案、勾选状态保持一致。
  - 重新渲染后步骤状态不丢失。
- 进度验证：
  - `tv_progress` 能正确显示 `已完成数/总数`。
  - `ProgressBar` 能根据完成比例更新。
  - 当新增未完成步骤时，总数增加，进度比例相应下降。
- 主题验证：
  - 进度条完成部分颜色来自 `?attr/colorPrimary`，不再依赖固定黑色。
- 回归验证：
  - 任务详情页现有番茄钟入口、任务基础信息展示不受影响。
