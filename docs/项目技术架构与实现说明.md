# MyPotato 项目技术架构与实现说明

## 1. 项目概述

### 1.1 项目定位

MyPotato 是一款基于 Android 原生开发的番茄钟 TODO 应用，融合了四象限优先级管理与番茄工作法，帮助用户聚焦重要任务。当前项目处于 **UI 骨架阶段**，核心页面结构已搭建完成，业务数据通过写死的 Mock 数据进行演示。

### 1.2 技术栈总览

| 技术领域 | 选型 | 说明 |
|---------|------|------|
| 开发语言 | Kotlin | 100% Kotlin 实现 |
| UI 框架 | ViewBinding + XML 布局 + Material 3 | 视图绑定启用，dataBinding 备用 |
| 导航 | Jetpack Navigation Component | 底部导航 + Fragment 切换 |
| 架构模式 | 单 Activity + 多 Fragment | MVVM 雏形，ViewModel 已接入 |
| 数据持久化 | Room | 已集成，仅 AppInfo 表，未接入业务数据 |
| 构建工具 | Gradle + Version Catalog | libs.versions.toml 统一管理依赖版本 |
| 最低 SDK | API 29 (Android 10) | minSdk = 29 |
| 目标 SDK | API 36 | targetSdk = 36 |
| 编译 SDK | API 36 | compileSdk = 36 |

## 3. 架构设计

### 3.1 整体架构：单 Activity + 多 Fragment

采用 Google 推荐的单 Activity 架构模式：

- [MainActivity](file:///e:/code/MyPotato/app/src/main/java/com/gordon/mypotato/MainActivity.kt) 作为应用的唯一入口 Activity
- 四个主要页面（Today / Tasks / Statistics / Settings）均以 Fragment 形式实现
- 通过 Jetpack Navigation Component 管理 Fragment 切换
- 深层页面（Task Detail / Pomodoro）以独立 Activity 形式存在，通过 Intent 跳转

**优点：**
- 职责清晰，Activity 专注于承载 Fragment 和底部导航
- Fragment 复用性好，生命周期管理更灵活
- Navigation 组件提供一致的导航体验

**局限：**
- Task Detail 和 Pomodoro 目前是独立 Activity，与主 Activity 的数据共享较麻烦
- 尚未引入完整的 MVVM 模式，各 Fragment 自行管理数据和状态

### 3.2 导航架构

**底部导航配置：**
- 菜单资源：[bottom_nav_menu.xml](file:///e:/code/MyPotato/app/src/main/res/menu/bottom_nav_menu.xml)
- 导航图：[main_nav_graph.xml](file:///e:/code/MyPotato/app/src/main/res/navigation/main_nav_graph.xml)
- 关联方式：`BottomNavigationView.setupWithNavController(navController)`

**导航结构：**
```
MainActivity (底部导航容器)
├── Today (startDestination)
├── Tasks
├── Statistics
└── Settings

独立 Activity：
├── TaskDetailActivity (从 Today/Tasks 跳转)
└── PomodoroActivity (从 TaskDetail 跳转)
```

**参数传递：**
- Fragment 间通过 Navigation Safe Args（当前未引入，使用 Intent extras 替代）
- Activity 间通过 Intent.putExtra() 传递 taskId、taskTitle 等字段

### 3.3 数据层架构

**Room 数据库配置：**
- 数据库类：[AppDatabase.kt](file:///e:/code/MyPotato/app/src/main/java/com/gordon/mypotato/data/AppDatabase.kt)
- 数据库名：`potato_db`
- 版本：1

**当前实体：**
- [AppInfo](file:///e:/code/MyPotato/app/src/main/java/com/gordon/mypotato/data/entity/AppInfo.kt)：应用信息表，包含 dbVersion 和 createTime

**后续规划方向：**
- 引入 Repository 模式统一数据访问入口
- 增加 Task、Step、Category 等业务实体
- 引入 FakeRepository 供 UI 骨架阶段使用，后续可无缝切换到 Room 实现

**核心功能：**

- **数据模型**：`StatisticsBarItem`（X轴标签 + 多个分段），`StatisticsBarSegment`（名称 + 分钟数 + 颜色）

**数据来源：**

- 单一系列颜色（橙色 `state_chart_orange`）

## 5. 数据层现状

### 5.1 Room 数据库配置

**Gradle 依赖：**
```
room-runtime + room-ktx（implementation）
room-compiler（ksp）
```

**数据库实例：**
- 采用双重检查锁单例模式（Double-Checked Locking）
- `@Volatile` 修饰 INSTANCE 保证可见性
- `synchronized` 保证线程安全
- 使用 `applicationContext` 避免内存泄漏

### 5.2 现有实体与 DAO

**AppInfo 实体：**
- 表名：`app_info`
- 字段：
  - `uid`：主键，自增
  - `db_version`：数据库版本
  - `create_time`：创建时间戳

**AppInfoDao 接口：**

## 7. 核心技术点

### 7.1 ViewBinding

**启用配置：** build.gradle 中 `buildFeatures { viewBinding = true }`

**使用模式：**
- Fragment：`FragmentXxxBinding.inflate(inflater, container, false)`，`onDestroyView()` 中置空 `_binding`
- Activity：`ActivityXxxBinding.inflate(layoutInflater)`
- 自定义布局（如 BottomSheet）：`XxxBinding.bind(contentView)`

**优点：**
- 类型安全，编译时检查
- 避免 findViewById 模板代码
- 空安全（通过 `_binding` 可空属性 + `binding` 非空属性的模式）

### 7.2 RecyclerView 适配器模式

**统一模式：**
- 适配器为 Fragment 内部私有类
- 通过构造函数注入点击回调 lambda
- ViewHolder 使用 ViewBinding
- `submitData()` 方法更新数据 + `notifyDataSetChanged()`

**局限：**
- 使用 `notifyDataSetChanged()` 全量刷新，无动画
- 未使用 DiffUtil 进行增量更新
- 未使用 ListAdapter

### 7.3 自定义 View 绘制

`StatisticsStackBarView` 展示了完整的自定义 View 绘制流程：

1. **定义 Paint**：网格线、基线、柱体、标签各一支 Paint
2. **onDraw 流程**：
   - 更新主题颜色
   - 计算绘图区域（考虑 padding）
   - 绘制网格（4 条水平分割线 + 1 条基线）
   - 遍历数据绘制柱体（从下往上堆叠，圆角矩形）
   - 绘制 X 轴标签（自适应密度）
3. **尺寸工具**：dp() / sp() 扩展方法
4. **数据驱动**：submitData() -> invalidate() -> onDraw()

### 7.4 BottomSheetDialog 使用

**创建流程：**
1. `BottomSheetDialog(context)` 创建实例
2. `layoutInflater.inflate()` 加载布局
3. `BottomSheetXxxBinding.bind()` 获取绑定
4. 绑定控件事件
5. `dialog.setContentView(content)` 设置内容
6. `dialog.show()` 显示

**应用场景：**
- Today 页 FAB 新建任务
- Tasks 页 FAB 新建任务
- 两页面复用同一个布局文件 `bottom_sheet_add_task_placeholder.xml`

## 8. 当前局限与后续规划

### 8.1 已知问题

| 问题 | 影响 | 优先级 |
|------|------|--------|
| MainActivity 强制浅色模式 | 主题切换功能无效 | 中 |

| Statistics 时间维度映射错位（今日/本周/本月 → DAY/MONTH/YEAR） | 文案与模式不一致 | 中 |
| Statistics 模块 C（类别步骤完成时间）容器缺失 | 与大纲三模块定义不符 | 高 |
| Statistics 类别筛选默认"全部"而非"仅长时" | 与 A4 默认仅长时要求不符 | 高 |
| TaskDetail 启动 Pomodoro 未传任务参数 | 番茄钟页无法获知任务上下文 | 中 |
| Pomodoro 计时未读取设置页 focusMinutes | 设置不生效 | 中 |
| Pomodoro 无 isLongTask 兜底校验 | 异常路径单次任务可进入 | 高 |
| RecyclerView 使用 notifyDataSetChanged | 性能较差，无动画 | 低 |

### 8.2 技术债

1. **缺少 Repository 层**：数据访问直接在 Fragment 中硬编码，后续接入 Room 改动面大
2. **缺少统一数据模型**：TodayTask、TaskUiModel 等多个数据类字段重复
3. **导航未使用 Safe Args**：Intent 传参类型不安全，容易写错 key
4. **缺少 ViewModel 分层**：各 Fragment 自行管理状态，未使用 ViewModel 保存状态
5. **深色模式未适配**：仅有 values-night/themes.xml 占位，MainActivity 强制浅色
6. **无单元测试/UI 测试**：测试覆盖率为 0

### 8.3 下阶段方向（Stage B）

参考 [UI骨架验收清单.md](file:///e:/code/MyPotato/docs/ui_skeleton/UI骨架验收清单.md) Stage B：

2. **Task Edit 页面**：支持新建和编辑任务

4. **导航参数规范化**：使用 Safe Args 或统一的参数协议
5. **规则一致性校验**：确保单次任务在所有入口都无法进入番茄钟
