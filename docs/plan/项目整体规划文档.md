## 一、项目概述

### 1.1 项目定位与目标

MyPotato 是一款**本地离线优先（Local First）**的番茄钟 TODO 应用，融合四象限优先级管理（Eisenhower Matrix）与番茄工作法（Pomodoro Technique），帮助用户聚焦重要任务。

**核心目标：**

- 以任务管理（Task Management）为基础，覆盖任务、步骤（Step）、分类（Category）、番茄钟会话（Pomodoro Session）全链路。
- 遵循 Material Design 3（Material3）设计规范，交互参考 Microsoft To Do 的易用性。
- 全量数据离线可用，不依赖云端服务；导入导出作为可选增强。
- 预留国际化（Internationalization, i18n）能力，默认支持简体中文（zh-rCN）与英文（en）。

### 1.2 项目背景与现状

当前项目处于 **Stage A（UI 骨架）完成**阶段，已交付可演示的页面壳与基础交互闭环：

- 单 Activity + 多 Fragment 架构落地，底部导航 4 入口齐全。
- Today / Tasks / TaskDetail / TaskEdit / Statistics / Settings / Pomodoro 七大页面 UI 已搭建。
- 业务数据以 Mock 形式写死在各页面内部，**页面间无数据互通**。
- Room 已集成但仅有 `AppInfo` 一张表，未接入业务实体。
- 统计页（Statistics）按计划延后，待数据库落地及番茄钟等核心功能完成后再确定展示内容。

> 说明：项目原路径为 `e:\code\MyPotato`，相关历史文档中仍保留该路径；当前工程实际位于 `c:\code\MyTodo`，包名保持 `com.gordon.mypotato` 不变。本规划文档统一以实际路径为准。

### 2.2 实现的技术要点

1. **ViewBinding 全量接入**：`buildFeatures.viewBinding = true`，Fragment 采用 `_binding` 可空 + `binding` 非空模式，`onDestroyView()` 置空避免内存泄漏。
2. **Jetpack Navigation Component**：`BottomNavigationView.setupWithNavController(navController)` 一行绑定；深层页（TaskDetail/Pomodoro）以独立 Activity + Intent 跳转。
3. **Room 单例（Double-Checked Locking）**：`@Volatile` + `synchronized` + `applicationContext`，开发期采用 `fallbackToDestructiveMigration`。
4. **自定义 View 绘制**：`StatisticsStackBarView` 完整实现 Canvas 绘制流程（Paint 定义 → onDraw 网格/基线/圆角柱体/X 轴标签 → 自适应密度 → 主题属性取色）。
5. **BottomSheetDialog 封装**：`AddTaskBottomSheetHelper` 统一封装新建任务弹窗，Today/Tasks 复用同一布局。
6. **主题属性（Theme Attributes）解耦**：颜色全部走 `?attr/colorXxx`，矢量图统一占位黑色 + `app:tint` 动态着色，为深色模式铺路。
7. **Material3 Elevation Overlay 局部关闭**：针对 BottomSheet 中卡片偏紫现象，采用 `ThemeOverlay.MyPotato.CardNoTint` 局部 Theme Overlay，保留全局视觉规范。
8. **RecyclerView 适配器模式**：内部私有 Adapter + 构造注入回调 lambda + ViewBinding。

### 2.3 已知问题与待解决项

| 问题 | 影响 | 优先级 |
|------|------|--------|
| 各页面 Mock 数据分散重复（5 处独立 Mock） | 数据不一致，维护成本高，页面间无同步 | 高 |
| 缺少 Repository 层与统一数据模型（TodayTask/TaskUiModel/StepMock 字段重复） | 后续接入 Room 改动面大 | 高 |
| MainActivity 强制浅色模式 | 主题切换功能无效 | 中 |
| Statistics 时间维度映射错位（今日/本周/本月 → DAY/MONTH/YEAR） | 文案与模式不一致 | 中 |
| Statistics 模块 C（类别步骤完成时间）容器缺失 | 与大纲三模块定义不符 | 高（统计页延后，暂不阻塞） |
| TaskDetail 启动 Pomodoro 未传任务参数 | 番茄钟页无法获知任务上下文 | 中 |
| Pomodoro 计时硬编码 25 分钟，未读取设置页 `focusMinutes` | 设置不生效 | 中 |
| Pomodoro 无 `isLongTask` 兜底校验 | 异常路径单次任务可进入 | 高 |
| 导航未使用 Safe Args | Intent 传参类型不安全 | 低 |
| RecyclerView 使用 `notifyDataSetChanged()` | 性能差、无动画，未用 DiffUtil/ListAdapter | 低 |
| 无单元测试/UI 测试 | 测试覆盖率为 0 | 中 |

## 四、技术架构设计

### 4.1 整体架构

采用 Google 推荐的 **单 Activity + 多 Fragment + MVVM** 架构：

- **MainActivity** 作为应用 Shell，承载底部导航与 NavHostFragment。
- 四个一级页面以 Fragment 实现；深层页（TaskDetail/TaskEdit/Pomodoro）当前为独立 Activity，后续可评估收编为 Fragment 或保留 Activity（视导航复杂度而定）。
- MVVM 雏形已具备（MainViewModel），但各 Fragment 尚未普遍接入 ViewModel，需在 Stage B 补齐。

### 4.2 技术栈

| 技术领域 | 选型 | 说明 |
|---------|------|------|
| 开发语言 | Kotlin | 100% Kotlin |
| UI 框架 | ViewBinding + XML + Material3 | dataBinding 备用 |
| 导航 | Jetpack Navigation Component | 底部导航 + Fragment 切换 |
| 架构模式 | 单 Activity + 多 Fragment + MVVM | ViewModel 已接入，Repository 待补 |
| 数据持久化 | Room | 已集成，业务实体待落地 |
| 异步 | Kotlin Coroutines + LiveData | Flow 待引入 |
| 构建工具 | Gradle + Version Catalog | `libs.versions.toml` 统一管理 |
| 最低 SDK | API 29（Android 10） | minSdk = 29 |
| 目标/编译 SDK | API 36 | targetSdk = compileSdk = 36 |
| 图表（统计页） | MPAndroidChart（首选）/ Vico（备选） | 待 Stage D 定型 |

### 4.3 数据层架构（重点）

**当前状态：** Room 已集成，仅有 `AppInfo` 表，业务数据完全 Mock 且分散。

**目标状态：** 引入 Repository 模式 + Room 业务实体 + LiveData/Flow 响应式刷新。

**目标实体设计（参考大纲）：**

| 实体 | 核心字段 | 关系 |
|------|---------|------|
| Category | id, name, colorHex, iconName | 1:N Task |
| Task | id, title, content, note, taskType, status, isUrgent, isImportant, categoryId, createdAt, plannedStartAt, finishedAt, totalDurationSec | 1:N TaskStep / PomodoroSession |
| TaskStep | id, taskId, title, note, sortOrder, status, completedAt, spentDurationSec | N:1 Task |
| PomodoroSession | id, taskId, stepId?, startedAt, endedAt, focusDurationSec, breakDurationSec, cycles, status | N:1 Task |

> 数据流转方案详见 [数据流转方案评估.md](file:///c:/code/MyTodo/docs/plan/数据流转方案评估.md)。

### 4.4 导航架构

```
MainActivity（底部导航容器）
├── Today（startDestination）
├── Tasks
├── Statistics
└── Settings

独立 Activity（深层页）：
├── TaskDetailActivity（从 Today/Tasks 跳转，传 taskId）
├── TaskEditActivity（新建/编辑，taskId 可空）
└── PomodoroActivity（从 TaskDetail 跳转，传 taskId + taskTitle）
```

**改进项：** 引入 Safe Args 或统一参数协议；TaskDetail → Pomodoro 补齐任务参数传递；Pomodoro 增加 `isLongTask` 兜底校验。

### 4.5 主题与 UI 规范

- 主题继承链：`Theme.MyPotato` → `Base.Theme.MyPotato` → `Theme.Material3.DayNight.NoActionBar`。
- 颜色全部走 `?attr/colorXxx` 主题属性，禁止硬编码色值。
- 矢量图统一占位黑色 + `app:tint` 动态着色。
- 深色模式架构已就绪：`values-night/themes.xml` 占位待填充；移除 `MainActivity` 强制浅色代码后即可生效。
- 控件统一：圆角 16dp、卡片 elevation 2dp、FAB elevation 6dp、触控目标 48dp。

### 5.2 各阶段目标与产出

**Stage B（下一步重点）：**
- 引入 Repository 接口 + FakeRepository（内存实现）。
- 定义统一 domain model（Task/TaskStep/Category）。
- 打通：新建任务 → 保存 → 列表刷新；编辑任务 → 保存 → 详情刷新；标记完成 → 状态即时可见。
- 导航参数规范化（Safe Args 或统一协议）。
- 规则一致性：单次任务在所有入口无法进入番茄钟。
- 各页面 ViewModel 补齐，状态由 ViewModel 持有。

**Stage C：**
- 落地 Room Entity/DAO/Database。
- 实现 RoomRepository，替换 FakeRepository（接口不变，UI 无感知）。
- 引入 LiveData/Flow 响应式刷新。
- 应用重启后数据持久化有效，交互行为与 Stage B 一致。

**Stage D：**
- 番茄钟会话落库（PomodoroSession）。
- 统计三模块闭环（时间段分布 / 完成情况 / 类别步骤完成时间）。
- 图表库选型定型并接入。
- 统计页"仅长时任务/步骤"口径说明与空态。

**Stage E：**
- 深色模式正式适配（移除强制浅色，填充 `values-night`）。
- i18n 全量落地（values-zh-rCN / values-en，文案零硬编码）。
- 关键流程单元测试 + UI 测试。
- 验收清单全量闭环。

## 七、风险评估

### 7.1 技术风险

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| Room 表结构设计不成熟导致返工 | 中 | 中 | 参考大纲已定义的详细数据模型；开发期用 `fallbackToDestructiveMigration`；字段集先最小后扩展 |
| 深层页用独立 Activity，与主页面数据共享困难 | 高 | 中 | Stage B 通过共享 ViewModel / SavedStateHandle 解决；长期可评估收编为 Fragment |
| 图表库选型延迟导致统计层重构 | 中 | 中 | Stage D 前完成 MPAndroidChart/Vico 评估，优先选成熟度高的 MPAndroidChart |
| 深色模式适配遗漏硬编码 | 中 | 低 | 主题属性解耦已完成，适配时仅需填充 `values-night`；适配后做全局回归 |
| AI 生成代码引入反模式 | 中 | 中 | 明确接口契约；关键路径人工 review；坚持卫语句（Guard Clauses）与单一职责 |

### 7.2 进度风险

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| 独立开发者精力分散导致进度滞后 | 高 | 中 | 严格按 Stage 顺序推进，不跨阶段并行大改；每阶段产出可验证 |
| 统计页延后导致后期集成压力 | 中 | 中 | Stage D 前预留统计接口；图表库提前选型 |
| Mock 数据迁移至 Repository 工作量被低估 | 中 | 中 | 分批迁移，每完成一页验证一页；FakeRepository 先行降低风险 |

### 7.3 质量风险

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| 无测试覆盖，回归依赖人工 | 高 | 高 | Stage E 补齐关键流程单元测试与 UI 测试；Stage B 起对 Repository 层先写契约测试 |
| 单次任务异常进入番茄钟的规则漏洞 | 中 | 高 | 在 TaskDetail 与 Pomodoro 双重校验 `taskType`；Stage B 纳入规则一致性验收 |
| 数据不一致（多页面状态不同步） | 高 | 中 | Repository + LiveData/Flow 响应式刷新，单一数据源 |

### 7.4 风险应对总原则

1. **小步快跑**：每阶段先数据结构后 UI 后测试，不跨阶段并行大改。
2. **接口先行**：Repository 接口先于实现，便于 Fake→Room 无缝切换。
3. **单一数据源**：所有页面数据统一来自 Repository，禁止页面内自行造数据。
4. **可验证产出**：每阶段输出变更清单、可运行截图、验收结果。

### 8.2 核心技术点梳理

本规划涉及的核心技术点与知识点：

1. **MVVM 架构模式**（Model-View-ViewModel）：ViewModel 持有 UI 状态，LiveData/Flow 响应式回推 UI。
2. **Repository 模式**：统一数据访问入口，屏蔽 Fake/Room 实现差异，是数据流转的关键抽象层。
3. **Room 持久化库**（Room Persistence Library）：Entity/DAO/Database 三件套，TypeConverter 处理复杂类型，外键级联策略。
4. **Jetpack Navigation Component**：NavHostFragment + Safe Args 类型安全传参。
5. **ViewBinding**：编译时类型安全视图绑定，避免 findViewById。
6. **Kotlin Coroutines + LiveData/Flow**：异步数据流与响应式 UI 刷新。
7. **Material Design 3 主题属性系统**（Theme Attributes）：`?attr/colorXxx` 解耦颜色与布局，支撑深色模式。
8. **Elevation Overlay 机制**：Material3 高度叠加层原理与局部 Theme Overlay 控制。
9. **单 Activity 架构**：Activity 作为 Shell，Fragment 承载页面，生命周期与导航解耦。
10. **Double-Checked Locking 单例模式**：Room 数据库实例的线程安全懒加载。
